# Block coverage audit - 11 October 2026

Reference: [Stackable catalog](https://wpstackable.com/custom-blocks/) and its individual block pages, including [Hero](https://wpstackable.com/hero-block/), [Card](https://wpstackable.com/card-block/), [Feature](https://wpstackable.com/feature-block/), and [Posts](https://wpstackable.com/blog-posts-block/). The supplied insertion screenshots inform the chooser interaction. These are independent implementations, not imported WordPress code.

All 44 catalog entries are registered (52 definitions including retained native blocks and internal Column). Registration is not a completeness rating. This revision adds real variations, content-preserving layout switching, named styling targets, responsive media backgrounds, and interactive canvas editing.

**Baseline** means the stated behavior has a control and shared rendering path. **Limited** identifies a narrower implementation or remaining reference gap. Neither rating means pixel-for-pixel Stackable parity. Every row also receives the supported shared Layout/Style/Advanced controls. Old nodes without a variation retain their existing rendering until a variation is selected.

## Remaining priorities and boundaries

1. Finish the limited reference-specific treatments above before describing this as full feature parity. In particular heading highlights/gradient text, gradient circle strokes and branded social presets remain narrower.
2. Variations use schematic thumbnails and independently designed CSS. They are not exact copies of every Stackable preset. Custom children remain in the additional-content area; no layout switch deletes children.
3. Shared styling targets currently support normal responsive styles. Hover/focus remain block-level; the UI does not claim responsive target hover/focus storage.
4. New interactive nodes support repeated-item editing. For older mixed Template structures, retain the existing List View actions when manipulating native field/binding wrappers.
5. No public visitor identity personalization, remote font loading, external design library, arbitrary executable SVG, Google Maps APIs, or WordPress integrations.

## Local review

Generate `.wrangler/block-review/block-layouts.html` by setting `BLOCK_REVIEW_PATH` to that absolute directory and running the shared framework suite. The HTML supports `?family=hero`, `?family=card`, etc. and `&dark`. The review fixture uses a local geometric image. The capture sweep contains 19 layout families - desktop/tablet/phone; screenshots are local review artifacts, not public content.

Validation results and remaining infrastructure caveats are recorded in `block-upgrade-validation.md`. Tasks persist separately; the existing pending review-task migration is not a block-framework schema change.
